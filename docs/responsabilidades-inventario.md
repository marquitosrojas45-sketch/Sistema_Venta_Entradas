# Ficha de Definición: Inventory Service (TP5 - Sección 8.1)

| Elemento | Definición |
| :--- | :--- |
| **1. Nombre** | **Inventory & Stock Service (`inventory-service`)** |
| **2. Responsabilidad principal** | Administración del catálogo de entradas a eventos, persistencia de existencias y **encapsulación de la exclusión mutua distribuida** que protege dicho stock frente a transacciones concurrentes. |
| **3. Operaciones** | - Consulta pública de catálogo y existencias disponibles.<br>- Creación, carga y reabastecimiento administrativo de stock.<br>- Reducción de existencias ante compras, coordinando el bloqueo distribuido en Redis y la persistencia en MongoDB. |
| **4. Reglas de negocio** | - El stock nunca puede ser negativo (`stock >= 0`).<br>- **Encapsulación del Lock (Devolución TP5/TP6):** Al ser el propietario único del stock, la concurrencia que lo protege se encapsula en este servicio. Toda reducción de existencias debe adquirir previamente el lock temporal en Redis (`lock:producto:<nombre>`) con TTL de 5000ms.<br>- Si el lock está ocupado por otra transacción simultánea, rechaza de inmediato con `HTTP 409 Conflict`.<br>- Si adquiere el lock, aplica decremento atómico (`$inc: { stock: -1 }`) en MongoDB bajo la condición `stock > 0`.<br>- En bloque `finally`, libera el lock mediante script Lua atómico validando el `ownerId` (UUID).<br>- La modificación manual de stock (`POST /api/inventario/stock`) está reservada exclusivamente a administradores (`ADMIN`). |
| **5. Datos propios** | - Base de datos NoSQL propia MongoDB (`tp6_inventario` en `inventory-db:27017`): Colección `inventarios` (`{ _id, producto, stock }`).<br>- Almacenamiento en memoria Redis (`inventory-redis:6379`): Claves de exclusión mutua (`lock:producto:...`). |
| **6. Endpoints** | - `GET /health` (Público): Comprobación de servicio y estado de conexiones a MongoDB y Redis.<br>- `GET /api/inventario` (Público): Consulta de catálogo y stock.<br>- `POST /api/inventario/stock` (Restringido `ADMIN`): Alta o modificación de stock.<br>- `PUT /api/inventario/reducir` (Autenticado `USER`/`ADMIN`): Reducción concurrente protegida con lock. |
| **7. Dependencias** | - Dependencias de microservicios: **Ninguna** (no consume a `user-service` ni a `checkout-service`). Valida criptográficamente el JWT propagado de manera autónoma (`HS256`).<br>- Dependencias de infraestructura: MongoDB (`inventory-db:27017`) y Redis (`redis:6379`). |
| **8. Fuera de alcance** | - Registro, autenticación y gestión de perfiles de usuario.<br>- Cobro, medios de pago y orquestación del flujo de checkout.<br>- Emisión de comprobantes finales de compra. |
| **9. Justificación** | Centraliza la integridad del dato más crítico del negocio (el stock de entradas). Al albergar el lock dentro de `inventory-service`, se evita que servicios externos manipulen llaves de Redis o queden desprotegidos ante nuevos canales de venta, eliminando el acoplamiento indebido de concurrencia. |
